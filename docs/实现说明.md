# 实现说明 — #1508 方法论知识接线

## 需求还原

企业知识库与多 Agent 协作系统（系列 50 单）的拆单之一。本单范围：
**将方法论资料组织为可检索、可引用的知识条目**。

验收标准：**提交结构模板、样例及查询结果**——即：
1. 一个结构模板（schema 定义方法论条目的骨架）；
2. 若干样例（把具体方法论按模板填充）；
3. 查询结果（证明条目可检索、可引用）。

## 设计

### 1. 结构模板

`schema/methodology_entry.schema.json`（draft-07）定义方法论条目的
9 个必填字段：

| 字段 | 作用 |
|---|---|
| `entry_id` | 全局唯一 ID（`method-` 前缀，支持含数字方法论如 5W2H）|
| `title` | 条目标题 |
| `methodology` | 方法论名称（Scrum / 5W2H / PDCA ...）|
| `topic` | 所属主题（用于分类检索）|
| `summary` | 一句话摘要 |
| `steps` | 可执行步骤（≥2 步，带顺序）|
| `applicable_scenarios` | 适用场景 |
| `cited_sources` | 引用来源（可回链，≥1 条）|
| `created_at` | 创建日期（YYYY-MM-DD）|

`additionalProperties: false` 拒绝未定义字段，保证条目不膨胀。

### 2. 样例

| 条目 | 方法论 | 主题 | 覆盖点 |
|---|---|---|---|
| method-scrum-01 | Scrum | 敏捷研发 | 三角色/四仪式/迭代 |
| method-5w2h-02 | 5W2H | 问题分析 | 数字方法论 ID 命名 |
| method-pdca-03 | PDCA | 质量改进 | 持续改进循环 |

每条都带至少 2 步可执行 steps 和至少 1 条 cited_sources。

### 3. 查询（可检索）

`KnowledgeBase.search(query, topic=None, methodology=None)`：
- 把 query 拆成单词（小写），在标题/topic/tags/methodology 建立的
  倒排索引里求并集；
- 可选 `topic` / `methodology` 精过滤；
- **无命中返回空列表而非报错**（对外是合法输入，不崩溃）。

测试覆盖：关键词检索（scrum）、标签检索（analysis）、中文主题过滤
（质量改进）、无命中空结果。

### 4. 引用（可引用）

每条 `cited_sources` 是 `[{source_id, reference, excerpt}]`，
`citations_for(entry_id)` 原样返回，查询结果可回链到原始资料——这
对应"组织为**可引用**的知识条目"这一句验收表达。

### 5. 校验与隔离

- 迷你 JSON Schema 子集校验器（与系列单同款），零第三方依赖；
- `load_dir` 跳过文件名含 `invalid` 的反例（只用于单元测试的拒绝路径）；
- 反例明确验证：缺字段/空数组/额外字段 → schema 拒绝（测试 12/12b/13）。
